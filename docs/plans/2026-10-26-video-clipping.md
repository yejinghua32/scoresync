# 视频剪辑功能规划

## 背景与目标

现有视频库可登记本地视频并创建记分项目，记分编辑器针对整段视频操作；尚不能选择保留/舍弃的画面区间并把保留内容拼接成新视频。新增独立剪辑项目，使使用者能够按实际视频帧标记、重开修改、预览并导出 MP4，导出成功后继续从视频库创建记分项目。

## 已确认的成功标准

1. 从视频库中的可读视频创建剪辑项目；关闭后重开，片段分类、名称及两个按项目配置的步长仍在。源视频不被复制或修改。
2. 剪辑页自上而下有视频预览、当前帧最大且前后帧渐小的重叠缩略图、保留帧区域、时间轴、舍弃帧区域；可通过时间轴跳到任意源帧。未标记帧有独立状态，不被误显示为已舍弃。
3. `↑`/`↓` 将当前暂选类型设为保留/舍弃并向后选取大步长帧，`→` 追加小步长帧，`←` 从暂选末尾减少小步长帧；默认分别为 10、5，项目内可修改。`Enter` 存档暂选，不自动切换类型；新标记覆盖重叠旧标记，同类相邻片段合并。仅存档状态在重开后存在。
4. 播放预览只遍历已存档的保留片段，浏览器直接在原视频中跳播；界面说明交界处可能与导出略有差异。空保留集不可导出。
5. 导出按原视频实际解码帧序号精确选择、按原顺序拼接全部保留片段，同步保留对应音频（无音轨的源视频仍可导出），输出 MP4；成功后自动登记回视频库。重复导出生成新文件/新资产，不覆盖既有结果。
6. 源视频缺失或大小/修改时间与建立帧索引时不符、索引失败、范围越界、正在进行其他导出或导出失败时，项目和已存档选择不丢失，返回中文可理解错误；没有半成品进入视频库。

## 范围与非目标

- 包含：单个视频资产对应一个可反复修改的剪辑项目；逐帧索引与按需缩略图；三态区间（保留、舍弃、未标记）；键盘和时间轴交互；浏览器跳播；异步 MP4 导出、进度/失败/取消与自动登记。
- 不包含：多视频拼接、重排片段、转场、变速、记分叠加、剪辑项目 JSON 备份、覆盖/自动删除旧导出、自动把源视频剪短。现有记分项目及导出含义不变。

## 现状与约束

- Spring Boot 3.2 / Java 17、SQLite/JDBC、纯 HTML/CSS/ES 模块、外部 FFmpeg/FFprobe；无前端构建流程。视频库入口为 `static/index.html` 和 `static/js/library.js`，现有媒体只能经 `/api/media/{assetId}` 流式访问。
- `FfmpegProbeService` 目前只返回宽高、时长、标称帧率及音轨，不提供逐帧映射。浏览器 `currentTime` 和标称帧率不能作为精确的帧边界；页面的跳播预览是明确接受的近似，缩略图和最终导出仍须以实际解码帧为依据。
- `schema.sql` 在每次启动时执行；旧库的新增表需在 `SchemaMigrationRunner` 中按存在性守卫创建，新列需要两处同步。纯 JUnit 测试通常使用内联 SQLite DDL，不加载这两套初始化机制。
- `render_job` 目前强制引用 `match_project`，`RenderJobService` 的互斥范围只覆盖记分导出；不能把剪辑任务伪装成记分任务。`video_asset.origin_type` 在新旧数据库中均只允许 `SCANNED`/`PICKED`。`registerPicked` 还要求文件在用户登记的视频目录内，不能直接用于导出的自动登记。
- 所有用户可见新错误使用中文；`ApiExceptionHandler` 返回统一的 `ApiError`。FFmpeg 启动时不是必备，创建项目/索引/导出遇到缺失的二进制须给出可恢复错误。

## 关键设计决定

### 帧、区间和持久化

- 用解码顺序从 0 开始的帧序号；区间采用 `[startFrame, endFrame)`，`↑`/`↓` 的 10 帧指从当前帧起恰好 10 帧，游标推进到下一帧，末尾按总帧数截断。小步长同理；`←` 只回退尚未存档的暂选，最多回退到暂选起点。空暂选不可提交。
- `clip_project` 引用 `video_asset`，记录项目名、两步长、建索引时的源文件大小和 mtime、总帧数等；`clip_segment` 保存不重叠的 KEEP/DROP 半开区间。未标记状态由区间空隙派生，不逐帧写数据库。提交重叠区间时在一个事务内拆分旧区间、覆盖、合并相邻同类区间；服务端校验范围、正整数步长和项目/视频关系，避免并发提交丢失区间。
- 创建时或首次打开时建立源视频的逐帧时间戳索引（含可变帧率）；索引和缩略图放数据目录缓存，按资产 ID + 文件大小/mtime 失效，不把所有缩略图或每帧记录塞进 SQLite。长视频索引/缩略图生成呈现加载和失败重试状态，限制同时请求数量及缓存占用。源文件变化时不把旧帧序号悄悄映射到新文件；阻止继续编辑/导出，保留项目供原文件恢复或用户另建项目。
- 项目重开默认保留最后持久化状态；暂选只在前端内存，按 `Enter` 才提交。按 `↑`/`↓` 可指定当前暂选的类别；`Enter` 后该类别不变，跳到其他位置可开始新暂选。覆盖重叠分类不会改动区间以外的帧。

### 预览、导出和资产

- 缩略图按当前帧附近少量帧按需获取，后端只接受剪辑项目 ID/帧序号，不接受任意文件路径；来源与媒体接口一致。精确帧图和游标由帧索引决定，浏览器预览按保留区间的帧时间戳跳播，无法保证交界处逐帧无缝；导出结果是精度基准。
- 导出开始时读取已存档区间快照；采用帧区间滤镜选视频帧并重编码成 MP4，依据索引时间戳切取对应音频并拼接，保留源片段顺序/时序。无音轨分支单独处理；不得用关键帧 `-c copy` 或按 `frameRate × seconds` 近似选帧。导出进行中的编辑不改变该任务的快照，下一次导出才反映新选择。
- 剪辑任务使用独立 `clip_render_job` 与工作目录，沿用现有编码参数、输出目录及进度/取消/启动恢复约定。抽取或复用共享的全进程导出占用检查，使记分导出和剪辑导出彼此冲突（409），启动时两类未完成任务均标记失败、清理临时文件；拒绝空保留集和不可读/已变化来源。
- 完成编码后先验证最终 MP4，再在配置的 exports 目录建立或复用 `video_source` 记录，用既有 `SCANNED` 类型登记这个新文件；路径唯一、大小/mtime 来自实际输出。仅成功登记后报告任务成功和新资产 ID。失败/取消不登记，清理工作文件及未登记的半成品；既有成功导出保留。删除被剪辑项目引用的视频资产须按现有“视频正在使用”规则拒绝；删除登记记录不删除磁盘文件。

### API 与边界

- 新增 `/api/clip-projects` 创建/列表、`/{id}` 查询与更新配置、`/{id}/segments` 提交区间、`/{id}/frames/{frameNo}/thumbnail` 缩略图、`/{id}/render-jobs` 创建任务；剪辑任务查询/取消/下载使用独立的 `/api/clip-render-jobs/{id}` 子路径。具体 DTO 和端点保持独立于记分项目，前端仍统一经 `static/js/api.js` 请求。
- 服务端拒绝无效类别、空/逆序/越界区间、非正步长、空保留集、失效源视频和同时导出；分别使用现有 400/404/409 模式及英文机器码，中文消息。无鉴权的本地应用不新增任意路径读写接口。

## 实施计划

### 任务 1：项目与区间持久化

- **文件/范围**：`src/main/resources/schema.sql`、`src/main/java/com/scoresync/config/SchemaMigrationRunner.java`、`domain/Clip*.java`、`repository/Clip*.java`、`service/ClipProjectService.java`、`web/ClipProjectController.java` 和 `web/dto/`；对应 `src/test/java/com/scoresync/repository/`、`service/`、`web/`、`config/` 测试。
- **接口与依赖**：以已有 `video_asset.id` 创建，保存两种步长和区间；为后续帧索引预留只读帧总数/来源指纹，首次建立总帧数后才允许提交区间。
- **完成条件**：创建/列表/重开项目，配置持久化；事务性覆盖、拆分、合并和未标记空隙正确；源资产不能在使用中被移除；旧数据库幂等迁移。覆盖首尾帧、重叠、重复提交、非法范围和并发提交不丢区间。
- **验证**：`mvn "-Dtest=ClipProjectRepositoryIntegrationTest,ClipProjectServiceTest,ClipProjectApiIntegrationTest,SchemaMigrationRunnerTest,VideoLibraryServiceTest" test`；对应类新增后执行。

### 任务 2：准确帧索引与缩略图

- **文件/范围**：`src/main/java/com/scoresync/service/render/FfmpegProbeService.java` 附近新增剪辑专用索引/缩略图服务、`config/AppProperties.java`（仅必要的缓存限制）、`web/ClipProjectController.java`，对应 `src/test/java/com/scoresync/service/` 测试。
- **接口与依赖**：任务 1 的项目和源资产 ID；输出帧数、每帧时间戳及限定尺寸的 PNG。生成过程不能阻塞应用启动，缓存按源指纹失效。
- **完成条件**：0 和最后一帧可定位，越界拒绝；VFR 不依赖平均帧率换算；请求不能读取库外路径；不可读/变化文件和工具缺失可恢复，缓存不会无限增长。
- **验证**：`mvn "-Dtest=ClipFrameIndexServiceTest,ClipThumbnailServiceTest,ClipProjectApiIntegrationTest" test`；测试用假探测/抽帧服务，不直接执行真实 FFmpeg。

### 任务 3：剪辑页和视频库入口

- **文件/范围**：`src/main/resources/static/index.html`、`static/js/library.js`、新增 `static/clip-editor.html`、`static/js/clip-editor.js`，以及 `static/css/app.css` 的局部剪辑样式；`StaticPageIntegrationTest.java`。
- **接口与依赖**：任务 1/2 的列表、区间、索引与缩略图 API；视频始终使用 `/api/media/{assetId}`。按项目显示两个可编辑步长，不影响原记分编辑器的秒级左右键。
- **完成条件**：可创建/重开；预览、重叠帧、保留带、时间轴、舍弃带顺序正确；键盘暂选与提交、覆盖旧标记、跳帧、空态/加载/错误状态、仅保留片段跳播可用；输入控件获焦时不劫持方向键/Enter；浏览器跳播边界的近似性质在相关状态可见。
- **验证**：`mvn "-Dtest=StaticPageIntegrationTest,ClipProjectApiIntegrationTest" test`；浏览器在桌面/窄视口用短片和长片手测缩略图层次、方向键、回车、跳转、重开和预览。

### 任务 4：导出、共享占用与自动登记

- **文件/范围**：`src/main/java/com/scoresync/service/render/RenderJobService.java`、该目录新增剪辑命令/任务服务、`repository/ClipRenderJobRepository.java`、`web/ClipRenderJobController.java`、`service/VideoLibraryService.java`、必要的 `VideoSourceRepository.java`/`VideoAssetRepository.java`，以及 schema/迁移与对应测试。
- **接口与依赖**：任务 1/2 的已存档 KEEP 区间、帧时间戳和源指纹；任务 3 显示进度、取消、下载及新资产入口。开始时冻结区间快照。
- **完成条件**：帧精确视频/同步音频、无音轨导出、空集拒绝；剪辑与记分导出全局互斥；取消/失败/重启状态一致；输出只在成功后登记并可由视频库创建记分项目；连续两次导出保留两份文件与资产。
- **验证**：`mvn "-Dtest=ClipFfmpegCommandFactoryTest,ClipRenderJobServiceTest,ClipRenderJobApiIntegrationTest,RenderJobServiceTest,VideoLibraryServiceTest" test`；纯测试以假服务/参数断言，不直接启动 FFmpeg。另用真实短片手测准确边界、音轨及浏览器可播放性。

### 任务 5：整体验收

- **文件/范围**：只补前述模块漏掉的回归测试或必要的使用说明；不顺手改动记分逻辑。
- **完成条件**：旧数据库、新安装、已占用视频、工具缺失、源变化、导出中取消、重开修改、重复导出及浏览器预览差异均有证据；最终 diff 无无关产物。
- **验证**：`mvn test`；使用显式 `SCORESYNC_DATA_DIR` 的临时数据目录和本机 FFmpeg/FFprobe 手动跑视频库→剪辑→预览→导出→自动登记→记分项目流程。若本机工具缺失，明确记录未完成的真实媒体验收。

## 顺序、风险与恢复

- 串行依赖：任务 1 → 任务 2 → 任务 3/4 → 任务 5。任务 3 和 4 可在 API 契约固定后处理互不重叠的页面与服务文件；最终集成验证由一个执行者完成。
- 逐帧索引对长视频有时间/磁盘开销，应限制生成并发、懒加载缩略图，给出可见进度/重试；索引缓存可删除重建，不是唯一真相。VFR 或损坏源素材需以实际解码帧测试，不能只依赖 `r_frame_rate`。
- 新表采用守卫式创建和迁移；不重建已有 `video_asset` 表、不扩大来源类型的 SQLite CHECK。回滚应用代码不修改已有记分数据；剪辑表及成功导出资产可保留，不能通过删除库文件回滚。
- 浏览器跳播只是近似预览，用户已接受边界差异；FFmpeg 输出仍需严格按帧验证。开放项：无。
